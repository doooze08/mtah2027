# ADR-002：先做跟踪坐标核心，后续引入 Smart Tagging 和录像证据

状态：已接受（项目负责人确认）。日期：2026-11-09。补充 [ADR-001](ADR-001-ATD-OBSERVATIONS.md) 中“引入额外输入时重新评估”的条件。

## 背景

- 规则允许把比赛提供的**全部自动数据**任意组合作为算法输入（[DATA.md](../DATA.md)、[RULES.md](../RULES.md)、[FAQ.md](../FAQ.md)）：
  tactical/broadcast 跟踪、Smart Tagging、homography、录像，以及我们自己的算法产出的中间结果。
  禁止的是人工标注或修正本场任何数据、使用本场的人工事件数据和私有答案；公开五分钟答案只能用于理解标签含义。
- ADR-001 把统一入口限定为 tactical ATD，这是为了让模拟和真实比赛共用同一份算法代码。这是**项目的选择**，不是规则的限制。
- 已知仅凭 ATD 难以判断的情况：
  - 对公开五分钟 D 段的定性检查显示，有的 D 开始时球在场内、正在移动、全程可见，很可能是哨响停表；
  - 死球期间不一定缺球，缺球也不一定和 D 同时开始。
  所以“出界 + 长段缺球”只能识别一部分 D。

## 决定

分两个阶段。

1. **当前阶段：只用跟踪坐标的核心算法。** 入口仍为 `predict(observations, metadata, config)`，用模拟数据开发和验证：
   控球确认、出界、缺球、重启。
2. **后续阶段：证据融合。** 当跟踪坐标无法判断或证据不足时，引入其他提供的数据：
   - **Smart Tagging（优先）**：定位球标记意味着一次重启，重启前有一段死球；阶段标记带球队，可作为控球方的先验。
     它是 Metrica 自动生成的，有漏标、错标（例如全场只有 5 个任意球标记，犯规停表明显漏标），
     时间戳表示阶段区间，不一定精确到重启那一帧。所以它只作为证据，不当作答案。
   - **录像（tactical，必要时 broadcast）**：例如识别球员整体停顿、裁判动作。成本较高，排在 Smart Tagging 之后。

Smart Tagging 不只是遇到疑难情况时的后备：哨响停表这类问题，原理上就需要跟踪坐标以外的证据。

## 后续阶段的接口约束

- `predict` 增加**可选**输入（例如 Smart Tagging 事件表）。不传时行为与当前完全相同，模拟数据和外部数据可以不提供它。
- 如需在模拟中测试融合层，由剧本事件生成“模拟 Smart Tagging”（定位球标记，加随机漏标和时间误差）。
  答案仍只由事件推导，生成标记时不得读取答案。
- 引入前先在本地做一次定性调研：定位球标记的时间戳和跟踪数据如何对齐（标记开始时球在哪、是否可见、离重启多久）。
  方法与公开五分钟 D 检查相同：AI 只写脚本、用合成数据测试，由人在本地运行，只把定性结论交给 AI。
  FAQ 禁止把比赛数据或其片段提供给托管大模型。

## 重新评估条件

- 跟踪坐标核心在模拟和外部数据上基本稳定，开始做融合层时；
- 发现 Smart Tagging 与跟踪数据的时间无法可靠对齐，或漏标严重到不足以作为证据时；
- 决定引入录像或 broadcast 时，先单独定义时间对齐和验证方法。
