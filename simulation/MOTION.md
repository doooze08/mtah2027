# 运动积木：地滚球与局部静止（PR 1）

本版仅新增地滚球和持球静止。抛物线 `kick_to()`、默认晃动、事件到标签的映射不变。
不修改观测层、算法输入接口或候选算法，不使用比赛答案。弹跳和阵型跟随留待 PR 2。

## 地滚球

```python
# 球必须已经贴地。先安排接球人的跑动，再确定滚动终点。
b.roll_to(1.8, player=receiver)
b.event("control_start", team="dfn")  # 剧本自己声明控制，运动积木不推断答案
b.hold(receiver, 1.0, in_front=0.0, still=True)

# 无人接的球：不在停止点虚构触球；停下后可以继续等待。
b.roll_to(4.0, point=(30.0, 69.0), arrival_contact=False)
b.wait(2.0)
```

`GroundRoll` 从起点到终点沿直线匀减速，球心恒为 0.11 m。距离 d、时长 T 对应：
`v0 = 2d/T`，`a = -2d/T²`；到点后位置固定、速度为 0，不外推、不反向。
`roll_to()` 默认记录出脚及接球触球；自由滚出时显式关闭终点触球。触球记录不是控球事件。
延长停球后的等待只延长片段覆盖范围，不改变之前的减速轨迹。

这是确定性测试模型，不是经过草地摩擦标定的物理引擎。生成后仍必须运行现有速度、加速度及触球自检。

## `hold(still=True)`

默认 `still=False` 完全沿用旧行为。开启后，指定时段内持球人和球保持现有位置，其他球员不变。
球必须已经在请求的 `height` 和 `in_front` 位置；否则报错，避免以瞬移实现静止。
需要先停球、降球或调整偏移时，先使用普通 `hold()`，再开始静止区间。

球员底层保存局部静止时段，不修改全局晃动幅度。区间外最多用 0.6 s 平滑接入/退出；
两个静止时段之间的空档短于 1.2 s 时各用半个空档过渡，不侵入静止时段。相邻静止段保持连续。
这些过渡是生成器的连续时间轨迹安排，会影响持球人紧邻区间的轨迹；其他球员完全不受影响。
静止与显式跑动相互重叠时，无论先安排哪一种，都报错。超出运动限制的故事仍由统一自检拒绝。
