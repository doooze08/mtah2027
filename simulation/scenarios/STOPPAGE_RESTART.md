# 长停顿与可选缺球

ST 用长死球段检查停顿边界和重启归属。正确答案只由剧本事件产生。
“数据商会在部分死球期间移除球坐标”是模拟假设，不是官方说明。
不读取本场追踪、答案或评分来选择参数。

## 故事和答案

表中按 H 发起故事描述。主客镜像交换 H/A，球场旋转 180°。
每段开头都有等待，因此完整答案从 D 开始。

| 子型 | 故事 | 中间死球段 | 完整答案 | 要检查的错误 |
|---|---|---|---|---|
| ST01 | H 带球遭 A 犯规；约一半故事在传球途中吹哨，球继续滚动，H 捡回摆好并开任意球 | 5–30 s | D → H → D → H | 球仍快速移动便维持活球；把犯规接触当作 A 控球；摆球提前结束 D |
| ST02 | H 慢速带球出边线，A 捡回，在线外长等待后掷入 | 5–30 s | D → H → D → A | 按捡球或举球结束 D；按出界前持球队确定重启归属 |
| ST03 | H 射门偏出底线，A 捡回，在门区摆球并开球门球 | 5–30 s | D → H → D → A | 球摆回场内便提前结束 D |
| ST04 | H 进球，A 把球送回中圈，等待后开球 | 30–90 s | D → H → D → A | 长停顿仍沿用 H；球回到中圈便提前结束 D |

等待时间从完成捡球、慢速运球和摆球所需的可行下限到表中上限随机抽取，
不把远距离捡球压缩到 5 s。运球平均速度不超过约 1.8 m/s，保留原自检上限。
ST01 快球分支在哨响时仍在场内，球按 1–3 m/s² 减速，D 从 stoppage 开始。
ST03 本轮固定为球门球，未增加角球分支。

地面重启的出球速度为 10–25 m/s 中的几何可行范围；接球速度 6–9 m/s，
传球距离不超过 35 m，停球 0.1–0.3 s。界外球平面出球速度 10–25 m/s。
任意球、球门球和中圈开球在实际踢出时记录 legal_restart；
界外球沿用 TI01 的约定，在球进入场内时记录 legal_restart。
不根据真实答案移动事件时刻。

## 缺球参数

默认关闭：不改变原有轨迹、事件、槽位、正确答案或输出数据文件。
开启后，只将观测表的 ball_x/ball_y 一起置为 NaN；全部球员坐标和速度不变。
算法元数据不含遮罩、事件、策略或场景名。调试轨迹保留完整球坐标。

| 参数 | 默认值 | 含义 |
|---|---|---|
| `--dead-ball-gaps` | 关闭 | 开启死球策略与可选活球短缺 |
| `--dead-ball-gap-weights WHOLE DELAYED VISIBLE` | 1 1 1 | 每段独立抽取整段缺球、延迟后缺球、全程可见的相对权重 |
| `--dead-ball-delay-range MIN MAX` | 2 5 | 延迟策略额外等待的秒数，均匀抽样 |
| `--live-ball-gap-rate RATE` | 13/5400 ≈ 0.002407 | 每活球秒的短缺发生率；0 关闭 |

三种策略各约 1/3 **是假设**，不是从官方答案估计的比例。出界也允许全程可见。
每段死球包括片段开头的等待，独立抽一次策略；整段策略允许 0–5 帧起点抖动，
延迟策略在此基础上加 2–5 s。恢复时刻为合法重启帧或其前一帧，等概率抽取；
这是观测模拟抖动，不改变实际踢出／掷入的事件或答案边界。
末尾未重启的死球不会提前恢复。延迟超过死球长度时，该段不产生缺球。

```text
真实状态  D 等待 │ H 活球 │ stoppage / ball_out ───── D ─────│ legal_restart → H/A
整段缺球  NaN…   │ 有球   │ 0–0.2 s 后 NaN………………恢复 │ 有球
延迟缺球  可见*  │ 有球   │ 先可见数秒，再 NaN………恢复 │ 有球
全程可见  有球   │ 有球   │             始终有球           │ 有球
```

`*` 短于延迟的开头等待全程可见。死球时仍可能看见快球、捡球或摆球，
因此不能把“缺球”和 D 当作完全相同的状态。

活球短缺长度为 1–4 帧（0.04–0.16 s），按活球时间的指数等待抽样；
前后各保留可见帧，不与死球缺球或另一短缺合并。不产生活球长缺球。
发生率按活球时长计，不是每个片段强制插入一次。
观测使用独立随机流，同故事镜像共享遮罩，不消耗剧本或槽位随机数。
manifest 记录全部参数、随机流和各片段每段死球所选策略及遮罩边界，不供算法读取。

## 运行与检查

```bash
.venv/bin/python -m simulation.generate \
  --dataset-id st_gaps_v1 --subtypes ST01,ST02,ST03,ST04 \
  --stories 50 --seed 0 --dead-ball-gaps
.venv/bin/python -m experiments.20261108_ball_gaps.ball_gaps --dataset st_gaps_v1
.venv/bin/python -m simulation.view --dataset st_gaps_v1 --experiment st_visual_review
```

已有编号不覆盖。统计脚本只使用 `--dataset`，不使用 tactical 数据入口。
查看器紫色色带表示算法缺球，球场上的紫色虚线球是仅供排查的干净轨迹。
每个子型 50 个种子、双镜像，共 400 片段，任一失败都会阻止整套写出。

## 与真实统计的差异

停顿密集片段的缺球率取决于场景比例、死球长度和策略权重，不要求等于整场的 40.7%。
等量 ST04 会提高 >30 s 的段数占比。长段应占缺球帧的主体，但延迟策略可以产生短尾段。
模拟始终有 22 名球员，没有球员漏检。ST01 的哨后快球、全程可见的死球是刻意保留的情况。
重现前一帧恢复可使统计脚本的前向差分速度偏低；消失前快慢也取决于停顿原因。
不强求速度 1.6/11.6 m/s、最近距离 0.7 m、线外比例 15% 或重现位移 10 m 精确匹配。
按现有脚本报告总表及各子型数字，不根据这些摘要反向选择种子或调整参数。
