# 基础控球场景族

`basic_possession.py` 自动发现 `BP01–BP03`，不需要修改注册表。这是干净输入下应逐帧全对的基础题，
不是参赛比赛的复刻，也不代表真实数据成绩。答案只由事件表生成，不调用候选算法。

| 子型 | 故事 | 完整答案序列（H 发起） | 捕捉的错误 |
|---|---|---|---|
| BP01 | 接球后在脚下完全静止持球，再传给队友，重复 2–4 次 | D → H | 把静止判死球、把传球途中判失去控球、把换接球队员判换队 |
| BP02 | 对手主动跑到传球路线上截球、停球并改变方向带走 | D → H → A | 提前按接近距离换权，或因平滑而推迟真实换权 |
| BP03 | 传球无人触及，直接越过边线，继续飞行到片段结束 | D → H → D | 出脚就判死球、球心越线就判完全出界、虚构接球触球 |

每个子型都由现有生成器产生 H/A 发起的两个版本，使用相同种子，位置旋转 180°。
共同开场为 1 s 死球、一次 0.4 s 短传合法重启、接球后稳定控制 2–3 s，沿用 V1 §2.5。
核心故事中每次脚下持球分别独立抽样 `Uniform(0.5, 3.0)` s，不通过重抽或缩放来满足总时长。
BP01 的每次持球都完全静止；接球位置即脚下位置，不额外添加球的滑移。短片段用带球动作补足时长。
只关闭参与球员的默认晃动：BP01/BP02 各 3 人，BP03 为 2 人；其余 19–20 人保留原晃动。
所有片段总时长 10–20 s；核心结束后保留 2–4 s 结果上下文。

BP02 的答案从 `control_start` 对应的 `ceil(25*t)` 帧换队，后续带离动作证明控制，不能反过来推迟边界。
BP03 使用连续球轨迹和现有 0.11 m 球半径求完全出界时刻；从对应边界帧起为 D。
出界后的轨迹仍是同一次自由飞行，没有接球者、额外触球或第二次控球。

**当前运动模型限制：** `kick_to()` 使用抛物线飞行，不是地滚球。0.4 s 短传、BP02 的 1.8 s 拦截传球、
BP03 的 4 s 出界高吊球，理论最高球心高度分别约 0.31 m、4.08 m、19.73 m
（同高度起落时 `z_max = 0.11 + 9.81*T²/8`）。地滚球需要等生成器支持后再补，不在本版模拟范围内。
算法输入的 ATD 宽表不含球高；动画中的高度属于 debug 干净轨迹，不能作为算法特征。

“必须全对”指固定干净集上的逐帧标签一致，包括边界帧；不以 `spellF1` 的区间容差代替逐帧检查。
开场死球和重启事件只用于生成答案；当前 ATD 观测层不向算法提供裁判信号。
因此不能把开场判对解释为已经解决“仅凭静止位置区分死球与活球持球”的可辨识性问题。
观测层以后增加缺失或噪声时，不能继续把“无歧义、必须全对”直接套在受损输入上。

```bash
# 从仓库根目录生成；每子型 5 个故事 × 主客镜像，共 30 个片段
.venv/bin/python -m simulation.generate --dataset-id basic_possession_v1 --subtypes BP01,BP02,BP03 --stories 5

# 场景回归检查：不读取真实比赛或公开答案
.venv/bin/python -m unittest discover -s tests -p 'test_basic_possession.py'
```

生成文件仍存于 `outputs/simulation_sets/<dataset_id>/`，不进 Git。
