# 模拟测试

这里保存模拟器代码和场景定义，与 `algorithms/` 中的控球算法分开。
当前只建立了目录约定；尚未实现生成器、场景或运行入口。

## 文件放置

```text
simulation/
├── README.md
└── scenarios/                         场景配置，进 Git

outputs/
├── simulation_sets/
│   └── <dataset_id>/                   一份固定测试集，不进 Git
│       ├── tracking.csv               逐帧位置观测，可包含噪声和缺失
│       ├── truth.csv                  独立正确标签，仅评分程序读取
│       └── manifest.json              生成配置、版本、种子及文件 SHA-256
└── <experiment_id>/
    └── simulation/
        └── <dataset_id>/
            ├── prediction.csv         该算法的预测
            ├── report.json            结构化指标
            └── report.md              按场景解释结果与局限
```

代码及场景定义进 Git；生成数据、答案、预测和报告放 `outputs/`，不进 Git。
算法参数和实验结论仍保存在 `experiments/<experiment_id>/`。
`simulation_sets` 是保留的输出目录名，不用作实验编号。

## 公平比较与复现

1. 先生成并固定一份测试集，再让所有候选算法读取相同的 `tracking.csv`。
2. 正确标签只交给评分程序；算法不得读取 `truth.csv` 或由它派生的信息。
3. 记录场景配置、随机种子、生成器代码版本和依赖版本。种子相同本身不足以保证复现。
4. 重建同一测试集后，以文件 SHA-256 检查数据一致性；不一致时不覆盖原数据、不混用比较结果。
5. 更换种子、场景或生成逻辑形成新测试集；所有候选应在这份新数据上重新运行。
6. 实验记录引用固定的 `dataset_id`、数据校验值、算法代码版本和参数，不修改已完成实验的配置。

生成器之后应依据独立定义的虚拟比赛过程产生正确标签，再生成位置观测；
不能用待测算法（例如最近球员规则）生成正确答案。

## 结果解释

重复跑同一数据、同一确定性算法，可检查复现性，但不会增加独立验证证据。
比较新随机种子或新场景有助于检查模拟条件下的稳定性，仍不能证明真实比赛效果。
报告应按场景列结果，并说明模拟假设及覆盖不到的情况。

只生成独立的虚拟场景，不把参赛比赛的人工标签或逐帧修正放入模拟测试集。
比赛数据使用边界见 [RULES.md](../RULES.md)。

`outputs/simulation_sets/` 是本机生成目录，被 Git 忽略；之后的生成器需自动创建它，
因此新克隆仓库中没有这个目录是正常的。
