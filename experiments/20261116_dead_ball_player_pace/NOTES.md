# 20261116 dead_ball_aware 球员整体速度裁决

## 问题

`dead_ball_aware` 只用球速、缺球和标签决定 D/H/A。外部弱标签里有一类长缺球：
球消失超过 5 s，坐标规则会把整段判成 D，但其中可能仍有活球。另一个相反的问题是：
死球中刚看到开球动作时，球员可能还没真正动起来，原规则会过早恢复活球。

实验加入两个**默认关闭**的开关，只让球员整体速度做否决或确认：

- **B1 `gap_requires_slow_players`**：长缺球要先看到球员整体慢下来，才判 D；
- **B2 `restart_requires_player_rise`**：死球中的开球动作后要看到球员整体动起来，才承认开球。

球员速度不改变开球帧、出界帧、换队帧或标签归属。关闭开关时输出应与旧版逐帧一致。

## 证据分工

| 用途 | 数据 | 规则 |
|---|---|---|
| 开发、选参数 | Metrica Sample Game 1/2 | 只在这里选 `p/W/Δ` |
| 外部检验 | Metrica Game 3 + SkillCorner 1925299 | 参数冻结后只读一次，不再改参数 |
| 模拟回归 | 18 个子型，开启集体速度、缺球和活球长缺球 | 只检查实现和其他子型，不作为有效性证据 |
| 本场诊断 | BAR-ATH tactical + 官方 Smart Tagging | 只报否决/拒绝计数，不读答案、不比较公开五分钟 |

模拟中的集体速度行为和这条规则来自同一个假设，模拟结果不能证明规则在真实数据上有效。
真实有效性只看 Game 3 和 SkillCorner 的弱标签检验。

## 特征与参数

- **F1**：有位置槽位速度的中位数；速度由相邻帧位置差分计算，不读 `_s` 列；
  按 1 s 后向平均（25 帧，最少 1 帧）。少于 5 个有限球员速度的帧为数据不足，记为 NaN。
- **固定阈值**：1.39 m/s，来自 PR #19 只用 Metrica Game 1/2 选出的分界值；本实验不重新选。
- **B1**：缺球段内 F1 低于 1.39 m/s 的有限帧占比 ≥ `gap_slow_fraction` 才判 D；
  分母只算有限帧。整段没有有限 F1 时保留原规则判 D；不满足占比时保留缺球前状态。
- **B2**：开球动作后 `player_rise_window_s` 内，F1 超过 1.39 m/s 或比动作前一帧上升至少
  `player_rise_delta_m_s`，才承认开球；否则继续 D，等下一个候选。窗口内没有有限 F1 时保留原开球。
- 参数网格（只用于开发）：`p ∈ {0.4, 0.6, 0.8}`，
  `W ∈ {1, 2, 3} s`，`Δ ∈ {0.3, 0.5, 0.8} m/s`。

开发集四个 clip 的平均 D F1：

| 臂 | 平均 D F1 |
|---|---:|
| off | 0.8591 |
| B1 p=0.4 / 0.6 / 0.8 | 0.8555 / 0.8516 / 0.8455 |
| B2 W=3, Δ=0.3 / 0.5 / 0.8 | 0.8503 / 0.8470 / 0.8437 |
| B2 W=2, Δ=0.3 | 0.8421 |
| B2 W=1, Δ=0.3 | 0.8195 |

每个开关取开发集 D F1 最高的参数，得到 `p=0.4`、`W=3 s`、`Δ=0.3 m/s`。
选择规则和完整网格在 `config.yaml`，`select_development.py` 可重放；选定后没有再看检验集调参。

## 模拟回归

验收集 `sim_pace_accept3` 共 108 个 clip，全部通过自检。短活球缺球率设为 0，
是为了让长缺球不被短缺球合并；这是模拟配置选择，不是算法改动。
54/108 个 clip 至少有一段 >5 s 缺球（58 段），其中 34/108 个 clip 的缺球与 H/A 真值重叠
（38 段，约 31%）。由于每个场景只有约 6–12 s，达不到“约一半 clip 有活球长缺球”的目标，
已在限制中如实记录。

四臂总误差：

| 臂 | core 全对 | core 错帧 | clip 错帧 | D 帧 | D→活球 | 活球→D |
|---|---:|---:|---:|---:|---:|---:|
| off | 36/108 | 7308 | 11388 | 26362 | 2368 | 8994 |
| gap | 48/108 | 5662 | 7586 | 26362 | 3522 | 3370 |
| restart | 36/108 | 7902 | 12038 | 26362 | 2356 | 9656 |
| both | 48/108 | 6256 | 8236 | 26362 | 3510 | 4032 |

B1 在缺球多的子型上把错误大幅压低，但这正是模拟器用同一“死球慢下来”假设生成的数据，
只能说明开关按设计工作，不能说明真实比赛有效。典型变化：BP01 core 0/6→4/6、
BP03 2/6→6/6、DC01/DC02 4/6→6/6、LC02 4/6→6/6；DC03 错帧 152→8、LC04 224→12。

B2 没有改善 ST05，还让 ST01 的错帧从 1340 增到 1640。

ST05 的四臂都没有通过：现有无标签坐标分支从未进入第二次 D（审计中

## 本场诊断

`real_diagnostics.py` 用官方 tactical 和 Smart Tagging，不读答案、不产生公开五分钟分数。
本场 199,319 帧。

F1 的两种算法对比：

| 指标 | 数值 |
|---|---:|
| 位置差分 F1 中位数 | 1.2178 m/s |
| `_s` F1 中位数 | 1.2627 m/s |
| 中位差（位置 − `_s`） | −0.0320 m/s |
| 平均绝对差 | 0.1143 m/s |
| P95 绝对差 | 0.3658 m/s |
| 相关系数 | 0.9834 |
| 两者都有限 / 仅位置有限 | 187,790 / 6,818 帧 |

两种速度高度相关，但位置差分整体略低；固定阈值 1.39 是在位置差分上选的，
因此算法坚持以位置差分为准，不混用 `_s`。

四臂诊断（只计数）：

| 臂 | D 帧 | 长缺球 | B1 否决 | 开球动作 | B2 拒绝 | 使用标签 |
|---|---:|---:|---:|---:|---:|---:|
| off | 113071 | 142 | 0 | 216 | 0 | 0 |
| gap | 108300 | 142 | 29 | 216 | 0 | 0 |
| restart | 116643 | 142 | 0 | 216 | 27 | 0 |
| both | 111386 | 142 | 29 | 216 | 27 | 0 |

- B1 否决 29/142 段长缺球，量级和 PR #19 Q4 的高速群（约 140 段中的十几到几十段）接近；
  这只是诊断，不代表准确率。
- B2 拒绝 27/216 个开球候选，D 帧比 off 多 3572。
- 官方 Smart Tagging 已传入，但基础配置使用旧保守标签模式，`tags_used=0`；
  因此本场四臂实际只验证了坐标分支，B2 的标签交互没有在本场得到检验。
  不把本场诊断当作标签模式或算法精度的证据。

## 结论

**不建议默认开启。** 理由：

1. 外部检验上 B1 在 G3 只带来 0.0007 的 D F1 变化，同时增加 D→活球错误；
   G1/G2 下降，SkillCorner 不变。没有稳定的净收益。
2. B2 在 G3 明显变差（D F1 −0.0117，活球→D 增加 1351 帧），SkillCorner 略好但方向不一致；
   模拟 ST05 也没有改善，因为坐标分支根本没有第二次 D。
3. 模拟回归中的大幅改善来自同一个“死球慢下来”假设，不能作为真实有效性证据；
   反例 ST03 和 ST01 显示真实代价存在。
4. 两个都开没有产生互补收益，G1/G2 反而比单开更差。

保留两个开关是为了复现和后续在有更长活球段、更可靠标签或能检测第二次 D 的场景中重测；
在任何新数据上重测前，参数不应再改。若未来默认启用，至少需要：
Game 3 上 D F1 稳定提高、dead→live 不增加，且 ST05/ST03 的代价有独立解释。

## 已知限制

- 外部标签是从数据商事件/阶段推出的弱标签，不是官方定义；Game 3/SkillCorner 的“真值”
  本身有漏标和阶段边界误差。
- B1 只在 >5 s 缺球上生效；短缺口、球可见的停表、出界仍由原规则处理。
- B2 只推迟已经检测到的开球；检测不到的第二次 D/开球（ST05 无标签分支）不会被修复。
- 真实诊断的标签模式未生效（`tags_used=0`），不能据此判断标签与 B2 的交互。
- ATD 的 `_s` 与位置差分 F1 虽高度相关，但仍有约 0.11 m/s 的平均绝对差；
  阈值不应跨速度定义混用。
- 模拟验收只有 34/108 个 clip 的缺球与活球真值重叠，低于“约一半”的目标；
  这是场景时长限制，不是算法筛选。
- 没有为任何单场、单个子型或反例加常数；所有参数来自开发集或固定阈值。
