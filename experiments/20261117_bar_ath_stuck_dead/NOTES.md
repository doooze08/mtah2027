# 本场“判 D 但球可见且快”的段落分类

## 1. 任务与边界

本实验只统计：BAR-ATH 当前 `dead_ball_aware` 可信标签模式下，预测为 D 的连续段里，
球可见、在场内、且速度达到出球速度的帧；含至少 1 s 这种帧的 D 段作为一个样本。
目的是估计 A2（长缺球结束后仍判 D）和 A3（出界后仍判 D）在本场大致有多大。

边界：

- 不读取 `evaluation/gt/`，不运行评分，不报告公开五分钟窗口的任何结果。
- 不修改 `algorithms/`；不手工标注、不修正追踪。
- Git 中不记录本场帧号或时间；逐段明细只写 `outputs/`，本文件只有汇总。
- 结果表示“像什么”，不是真实对错，也不表示修复后一定涨分。

## 2. 数据与配置

- 数据：本场 tactical ATD；只取两个计分半场，边界沿用 PR #25。
- 标签：官方 Smart Tagging；可信标签模式，参数沿用
  `experiments/20261111_dead_ball_trusted_tags`（`trusted_tags: true`）。
- 当前预测：同一配置下的 `dead_ball_aware` 输出；只用它确定“预测为 D”的连续段，
  不做评分。
- “快球帧”：球坐标已知、未出界（按 `ball_radius_m` 留边）、按相邻帧位置差计算的
  球速不低于配置中的 `release_speed_m_s`（4.0 m/s）。
- 样本：一个预测 D 段内至少 1 s（25 帧）满足上述条件。
- “静止”：球速不高于 0.5 m/s 的连续至少 1 s；0.5 仅是描述用线，不是规则。
- “球员快/慢”沿用 PR #24 的描述线：卡住期间 `f1_speed_med` 不高于 1.575 m/s 为慢。

分组在运行前写定，结果出来之后没有修改：

- **像真死球**：满足任一条件——卡住期间球在定位球位置（角旗、球门区、中圈）
  静止至少 1 s 且 D 以发球/传球确认结束；或第一个快球帧被 SET PIECES 覆盖；
  或卡住期间球员慢（F1 中位数不高于 1.575 m/s）。
- **像卡住的活球**：第一个快球帧不被 SET PIECES/GOALS 覆盖，卡住期间球员快
  （F1 中位数高于 1.575 m/s），且有球员持续控球。优先级低于“像真死球”。
- **不确定**：其余。

判定是否值得修也预先写定：像卡住的活球总时长不超过 1 分钟，记录后结束；
至少 2 分钟，另开任务设计修复；介于两者之间，看录像后再由团队决定。

## 3. 样本量

共 **45 段**，卡住时长合计 **913.8 s**；这些段本身的 D 时长合计 **1,827.0 s**。
PR #21 在同一配置下记录 47 段，本次为 45 段；差异来自当前可信标签配置和精确的
快球帧门槛，未为对齐数字调整任何线。

第一个快球帧的位置：

| 位置 | 段数 |
|---|---:|
| 长缺球结束后（A2） | 43 |
| 出界后（A3） | 1 |
| 标签窗口内 | 1 |
| 其他 | 0 |

A2 占绝大多数；A3 在本场很少。这个分布与“球通常在发球后才重现，重现时就很快”
的预期一致。

D 开始原因：

| 开始原因 | 段数 |
|---|---:|
| 出界 | 20 |
| 长缺球 | 24 |
| 标签支持的可见停表 | 0 |
| 其他 | 1 |

D 结束方式：识别到发球 25 段、传球确认 19 段、半场结束 1 段、其他 0 段。

与标签的重叠（可重叠计数）：SET PIECES 31 段、GOALS 3 段、其他阶段标签 39 段、
不与任何标签重叠 3 段。互斥覆盖为：SET PIECES 31 段、其他阶段 11 段、无标签 3 段。

卡住期间的持续控球方（同一套控球门槛的薄诊断，不调用算法）：

| 控球方 | 段数 |
|---|---:|
| 仅 H | 15 |
| 仅 A | 10 |
| 两队都出现 | 16 |
| 无 | 4 |

球在卡住期间至少 1 s 静止的有 8 段，全部落在“像真死球”：静止类别为其他位置 6 段、
球门区 1 段、出界/边线附近 1 段。只有球门区那 1 段同时满足“定位球位置静止且
D 以发球/传球确认结束”，其余静止段靠 SET PIECES 覆盖或球员慢归入真死球。

从 D 开始到第一个快球帧：全样本中位数 10.8 s（四分位 4.9–26.7 s）；
“像卡住的活球”中位数 10.8 s。该值只描述预测 D 段内的等待，不是本场时间。

## 4. 分组结果

| 组 | 段数 | 卡住时长/s | D 时长/s | A2 段数 | A3 段数 | 标签窗口段数 |
|---|---:|---:|---:|---:|---:|---:|
| 像真死球 | 36 | 814.7 | 1,645.1 | 34 | 1 | 1 |
| 像卡住的活球 | 9 | 99.1 | 181.8 | 9 | 0 | 0 |
| 不确定 | 0 | 0.0 | 0.0 | 0 | 0 | 0 |

“像真死球”的 36 段中，快球帧被 SET PIECES 覆盖 14 段；球员慢 10 段；
两者同时 11 段；球在定位球位置静止后发出且快球帧在 SET PIECES 内 1 段。
这些条件可以重叠。

“像卡住的活球”的 9 段全部是 A2：

- 开始原因：长缺球 6 段、出界 3 段。
- D 结束：传球确认 8 段、识别到发球 1 段。
- 标签覆盖：其他阶段 6 段、SET PIECES 2 段、无标签 1 段；但第一个快球帧
  本身都不在 SET PIECES/GOALS 内。
- 持续控球：仅 H 4 段、仅 A 1 段、两队都出现 4 段。
- 卡住时长：合计 99.1 s；最短 2.6 s，中位数 6.0 s，最长 28.5 s。
- 球员 F1 中位数均高于 1.575 m/s；不是“球员也慢”的段。

9 段里有 2 段整段与 SET PIECES 标签重叠，但快球帧不在标签内；这说明标签窗口
可能晚于缺球结束，不能只用“整段是否与 SET PIECES 重叠”判断快球帧是否在死球中。
本实验因此把标签覆盖同时记在段级和快球帧级。

## 5. 是否值得修

按预先写定的规则：像卡住的活球合计 **99.1 s**，介于 60 s 和 120 s 之间，
结论是 **看录像后再由团队决定**，不是“明确不值得”，也不是“明确值得设计”。

这只是当前预测下的“像卡住的活球”时长；没有答案，不能据此估计修复后的分数变化。
A2 占 43/45，说明如果将来处理这类错误，重点应在“长缺球结束后球已重现”的路径，
而不是出界路径；但本场 A3 只有 1 段，不能据此判断其他比赛。

## 6. 限制

- 分组是描述性规则，不是真实标签。“慢球员”条件会把死球中慢下来的段判成
  “像真死球”；死球中仍在跑、又没有 SET PIECES 覆盖的段，若同时有持续控球，
  可能落到“像卡住的活球”。本次没有“不确定”段，不等于分组天然正确。
- 持续控球是薄诊断：只复用控球半径、相对速度和确认时长，不调用
  `sustained_control` 或 `dead_ball_aware` 的状态机；它只说明“球附近有稳定控球关系”，
  不证明控球方就是规则意义上的控球方。
- 标签覆盖按半开区间计算；SET PIECES 和 GOALS 可以重叠。段级覆盖不等于
  快球帧覆盖；两者都保留。
- “标签支持的可见停表”为 0 段是当前可信配置下的结果，不代表标签从不支持可见停表；
  本场这些段主要从出界或长缺球开始。
- 快球帧阈值来自配置（4.0 m/s），球员快慢线来自 PR #24（1.575 m/s）；
  没有为本场调整。球静止线 0.5 m/s 只用于描述，不参与分组以外的决策。
- 没有单元测试；这是只读诊断脚本。全仓库测试另行运行。
- 逐段明细在 `outputs/20261117_bar_ath_stuck_dead/segments.csv`，含时间，已被 Git 忽略；
  本文件不写帧号或时间。
