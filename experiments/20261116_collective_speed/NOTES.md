# 球员整体速度能否区分死球和活球（2026-11-16）

本实验只测量，不改算法、模拟器、转换代码或已完成实验。目标是回答：全场球员整体速度
对 D / H·A 有没有区分度、段级是否更稳、停表后多快能看到减速、开球后球员和球谁先加速，
以及本场无答案数据上的长缺球段呈现什么形态。

**边界**：没有读取 BAR-ATH 公开五分钟答案、评分或派生报告；没有在代码或本文写本场
帧号或时刻。外部弱标签来自 PR #17（commit `cbfa3c7`）生成的数据集，本实验只读取
`outputs/simulation_sets/ext_*`，没有修改 `external/`。

## 1. 固定特征定义（先定后看）

逐帧只用 3 个特征：

| 特征 | 定义 |
|---|---|
| `F1` | 当前帧有有限速度的槽位速度中位数（m/s） |
| `F2` | 这些槽位中速度严格 > 2 m/s 的比例 |
| `F3` | `F1(t) − F1(t−25)`，即过去 1 s 的变化量（m/s per s） |

- `F1`、`F2` 先做**后向** 1 s 滑动平均（25 frame，至少 1 个样本）。选后向而不是居中，
  是为了不让特征看到未来，便于以后做在线确认。
- 当前帧有有限速度的槽位少于 5 个时，该帧不合格，平滑后仍置 NaN；不用前一秒的值
  填补整段追踪缺口。
- `F3` 用已经平滑的 `F1` 做 25 frame 差分；它本身不再额外平滑，避免二次延迟。
- 守门员无法从匿名槽位识别，一律计入；不区分位置、球队或球员身份。
- 外部数据的 `_s` 由位置差分得到；本场 ATD 用原始速度列，二者平滑程度不同。两边都
  做 1 s 后向平均，但短时噪声特征不能视为完全相同。

## 3. Q1：能不能分开

### 3.1 逐帧（D vs H/A，X 不计）

图：`outputs/20261116_collective_speed/q1_frame_dist.png`（D 与 H/A 的箱线图，四个数据集）。

| 场次 | F1 D 中位（IQR） | F1 H/A 中位（IQR） | F1 AUC | F2 D 中位（IQR） | F2 H/A 中位（IQR） | F2 AUC |
|---|---:|---:|---:|---:|---:|---:|
| Game 1 | 0.99（0.67–1.28） | 1.79（1.33–2.65） | 0.843 | 0.053（0.004–0.138） | 0.429（0.242–0.665） | 0.865 |
| Game 2 | 1.04（0.69–1.30） | 1.73（1.27–2.48） | 0.807 | 0.075（0.024–0.156） | 0.413（0.225–0.629） | 0.848 |
| Game 3 | 0.98（0.66–1.30） | 1.90（1.40–2.60） | 0.845 | 0.089（0.027–0.196） | 0.469（0.284–0.653） | 0.858 |
| SkillCorner | 1.08（0.76–1.43） | 1.95（1.42–2.69） | 0.830 | 0.078（0.011–0.215） | 0.478（0.275–0.711） | 0.864 |

AUC 的方向是 `P(活球值 > 死球值)`，0.5 为无区分。F1 和 F2 都有中等区分度，Metrica
逐帧 AUC 0.81–0.86；死球 F1 中位约 1.0 m/s，活球约 1.7–1.9 m/s。重叠也很明显：
死球 IQR 上缘约 1.3 m/s，活球 IQR 下缘约 1.3–1.4 m/s，慢节奏活球和死球中的跑位准备
会落在同一区间。

### 3.2 逐段（>5 s 缺球，按弱标签多数分；只作敏感性检查）

图：`outputs/20261116_collective_speed/q1_segments.png`（散点为每段均值）。

| 场次 | 可分类段（死/活） | 活球段首事件=SET PIECE | F1 死球段均值中位 | F1 活球段均值中位 | F1 AUC | F2 死球段均值中位 | F2 活球段均值中位 | F2 AUC |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| Game 1 | 73 / 9 | 2/9 | 1.07 | 1.21 | 0.654 | 0.089 | 0.108 | 0.524 |
| Game 2 | 72 / 11 | 6/11 | 1.07 | 1.28 | 0.556 | 0.109 | 0.154 | 0.598 |
| Game 3 | 74 / 14 | 11/14 | 1.10 | 1.31 | 0.554 | 0.155 | 0.179 | 0.514 |

“活球段首事件=SET PIECE”统计的是每场弱标签多数为活球的 >5 s 缺球段中，缺球结束后
第一个数据商事件是 `SET PIECE` 的段数（代码写进 `q1_segment_restart.csv`）。这些段很可能
是弱标签漏掉的死球：真正的停顿起点可能是 `BALL LOST OFFSIDE`、`HAND BALL` 等不在当前
停顿事件列表里的事件，缺球结束时才出现任意球/界外球。

去掉这些疑似漏标段后：

| 场次 | 活球段（全部→去掉后） | F1 AUC（全部→去掉后） | F2 AUC（全部→去掉后） |
|---|---:|---:|---:|
| Game 1 | 9 → 7 | 0.654 → 0.718 | 0.524 → 0.640 |
| Game 2 | 11 → 5 | 0.556 → 0.789 | 0.598 → 0.789 |
| Game 3 | 14 → 3 | 0.554 → 0.477 | 0.514 → 0.446 |

**段级样本过少、弱标签有噪声，段级区分度未能可靠测量。** 每场只有 9–14 个活球段；
其中 2/9、6/11、11/14 的缺球后首事件是 `SET PIECE`，去掉后 Game 1/2 的 F1 AUC 虽升到
0.718/0.789，但 Game 3 只剩 3 个活球段，AUC 0.477 已没有解释力。剩余活球段中也有
平均 F1 很低（例如 0.22、0.49、0.69、0.77、0.80 m/s）的段，无法区分是慢节奏活球还是
漏标。因此这些段级数字只作敏感性检查，不能据此得出“单靠速度不能判定缺球段是否活球”；
逐帧结论（AUC 0.81–0.86）不受影响。

### 3.3 留出检查

只用 Game 1/2 的逐帧 F1 选一个分界值：在 0–5 m/s、步长 0.01 上最大化平衡正确率。
选出的阈值是 **1.39 m/s**（低于阈值判 D，高于判活球），Game 1/2 上平衡正确率 0.761、
逐帧正确率 0.749（286,162 frame）。原样用到 Game 3：

- 逐帧：142,698 frame，准确率 0.768，平衡正确率 0.778；D 判对 32,473、判错 8,050；
  活球判对 77,156、判错 25,019。
- 逐段：88 段，准确率 0.670，平衡正确率 **0.514**；只有 4/14 个活球段被判对，
  19 个死球段被判成活球。把逐帧阈值直接套到段均值上会明显高估“活球缺球”。但段级
  弱标签本身有漏标（见 3.2），这个准确率不能当作可靠的段级验证。

逐帧阈值从 Game 1/2 到 Game 3 没有明显下降（平衡正确率 0.761 → 0.778），说明这个
阈值在逐帧层面跨场还算稳定；段级样本和标签都不足以支持稳定结论（见 3.2）。

## 4. Q2：停表后多快能看到减速

图：`outputs/20261116_collective_speed/q2_curves.png`（F1 中位数，D-start 与随机活球
PASS 对照）和 `q2_f3_curves.png`（F3 中位数）。

零点是产生 D 的停顿开始事件（`FAULT RECEIVED`、`CHALLENGE FAULT`、`BALL OUT`、
`SHOT OUT`），只取弱标签在该帧确实为 D 的事件。对照组是每场同样数量的、弱标签为
H/A 的随机 PASS 事件（固定随机种子）。

| 场次 | D-start 事件数 | F1 中位曲线 50% 下降时刻 | 对照 PASS 同时刻 | D 的 F3 最低时刻 / 值 | 对照 F3 最低时刻 / 值 |
|---|---:|---:|---:|---:|---:|
| Game 1 | 138 | **2.12 s** | 无（≥20 s 内未持续下降） | 1.32 s / −0.319 | 10.04 s / −0.109 |
| Game 2 | 132 | **1.72 s** | 无 | 1.72 s / −0.274 | 8.08 s / −0.122 |
| Game 3 | 114 | **2.36 s** | 18.96 s（不是即时反应） | 1.20 s / −0.369 | 8.36 s / −0.102 |

F1 中位曲线在 D-start 后约 **1.7–2.4 s** 出现持续下降；F3 的最低点更早，约
**1.2–1.7 s**。对照组的中位曲线没有这种即时下降（Game 3 的 18.96 s 是窗口后段的
另一个波动，不是停表后的反应），F3 最低点也晚到 8–10 s，幅度只有 −0.10 至 −0.12。

**注意**：逐事件的“50% 下降”很不稳——对照组也有 99–111 个事件被这个逐事件指标
判成“有下降”，因为活球中本来就有短时减速。因此本文把**中位曲线**作为主要证据，
逐事件数字只作辅助，不能单独用于判 D。Metrica 的犯规事件时间是犯规发生时刻，不一定是
裁判哨响时刻，所以“1.7–2.4 s”是事件时间到可见减速的延迟，不是严格哨响延迟。

## 5. Q3：开球后多快能看到加速

图：`outputs/20261116_collective_speed/q3_curves.png`（F1 与球速中位曲线，SET PIECE = 0）。

“开始加速”定义为相对事件前的基线（−10 至 −2 s 中位）首次持续高出：球员 F1
+0.2 m/s、球速 +0.5 m/s，并要求保持 0.5 s。另给“半升时间”（到 +10 s 窗口峰值的一半）
作辅助；后者受球速在 0 s 尖峰后回落影响，数值不直观。

| 场次 | SET PIECE 数 | 球员加速开始（中位） | 球加速开始（中位） | 成对 n | 球员比球晚（中位，IQR） | F3 峰值时刻 |
|---|---:|---:|---:|---:|---:|---:|
| Game 1 | 75 | 1.40 s | 0.52 s | 16 | **+1.16 s**（−0.36 至 +2.37） | 2.60 s |
| Game 2 | 79 | 1.54 s | 0.30 s | 16 | **+1.84 s**（+0.71 至 +3.02） | 3.28 s |
| Game 3 | 90 | 1.42 s | 0.16 s | 28 | **+2.50 s**（+0.62 至 +4.18） | 2.32 s |

球的加速开始都在 0.2–0.5 s；球员整体 F1 的可见上升约 1.4–1.5 s，比球晚
**1.2–1.8 s**（Game 3 成对中位 2.5 s，略高于预期上限）。F3 峰值约 2.3–3.3 s，说明
球员加速更平缓、持续时间更长。球速在 SET PIECE 后立即出现尖峰然后回落；球员 F1 则是
缓慢上升。

半升时间（到 +10 s 窗口峰值的一半）球员为 3.28/3.68/3.64 s、球为 3.66/3.20/3.42 s，
成对差 0.90/1.36/1.44 s；因为球速在 0 s 尖峰后回落，这个绝对数值不直观，只作辅助。

可用性有限：球加速开始只在 16/24/33 个 SET PIECE 上可测（共 75/79/90），因为部分
球速在事件帧缺失或上升不足 0.5 m/s；球员加速开始覆盖 69/66/80 个。结论主要看
成对的 16/16/28 个事件，外推要谨慎。

## 6. Q4：本场无答案的长缺球段

本场 tactical ATD 共 **142 段** >5 s 缺球；139 段有可用 F1/F2，3 段没有。没有标签，
以下只是分布观察。

图：`outputs/20261116_collective_speed/q4_hist.png`（每段平均 F1/F2 直方图）。

- 段平均 F1：中位 **1.190 m/s**，Q1 0.909，Q3 1.479。
- 段平均 F2：中位 **0.094**，Q1 0.040，Q3 0.229。
- 1 维 2-means（F1）：121 段中心 1.099 m/s，18 段中心 2.788 m/s；分界 2.032，
  两群间隔只有 0.229 m/s，整体标准差 0.689，群内标准差 0.392。
- 1 维 2-means（F2）：115 段中心 0.101，24 段中心 0.565；分界 0.338。

直方图是“一个大的低速群 + 一个高速尾群”，不是两群等量、间隔清楚的双峰；中间
1.6–2.0 m/s 仍有段。因此可以描述为“大多数长缺球段速度低，少数明显高”，但不能说
已经明显分成两个互不重叠的群。高尾群 18 段（F1）很可能对应活球缺球，但本场没有答案，
不能确认。

把 Q1 的逐帧分界值 1.39 m/s 直接套到段平均 F1：139 段中 **42 段被判为“活球缺球”**，
97 段判为死球。这个数字比 2-means 的高尾群（18 段）大得多；原因是阈值是为逐帧选的，
不是为段均选择的，不能把 42 当作活球段的真实数量。

## 7. 结论

### 实测

1. 逐帧层面，球员整体速度对 D / H·A 有中等区分度：Metrica F1 AUC 0.81–0.85，
   F2 AUC 0.85–0.86；SkillCorner F1 AUC 0.83、F2 0.86。死球 F1 中位约 1.0 m/s，
   活球约 1.7–1.9 m/s；分布明显重叠。
2. 逐段原始弱标签下 F1 AUC 0.55–0.65，F2 AUC 0.51–0.60，低于逐帧；但活球段只有
   9–14 个，且 2/9、6/11、11/14 的缺球后首事件是 `SET PIECE`（疑似漏标死球）。去掉后
   剩 7/5/3 段，F1 AUC 0.718/0.789/0.477，Game 3 样本过少。段级区分度未能可靠测量，
   不能据此下结论。
3. Game 1/2 选出的逐帧阈值 1.39 m/s 用到 Game 3：逐帧准确率 0.768、平衡正确率
   0.778，没有明显下降；但段级准确率 0.670、平衡正确率 0.514。
4. 停表事件后，F1 中位曲线约 1.7–2.4 s 出现持续下降；F3 最低点约 1.2–1.7 s。
   随机活球 PASS 对照没有这种即时下降（Game 3 的 19 s 不是停表反应）。
5. 开球后球先加速（0.2–0.5 s），球员整体 F1 约 1.4–1.5 s 才可见上升，比球晚
   1.2–1.8 s（Game 3 成对中位 2.5 s）；球员上升更平缓，F3 峰值约 2.3–3.3 s。
6. 本场 142 段 >5 s 缺球中，段平均 F1 中位 1.19 m/s；2-means 给出 121 段低速群
   （中心 1.10）和 18 段高速尾群（中心 2.79），但不是干净的双峰。逐帧阈值 1.39
   会把 42/139 段判为“活球缺球”。

### 推断

- 球员整体速度更适合做**确认**信号：在已有缺球/停顿候选后，等 1–2 s 看整体速度是否
  持续偏低，而不是用它精确定位哨响或 D 的起点。它能缓解“活球中途缺球 >5 s 被直接判
  D”的一部分误判，但会引入 1–2 s 延迟。
- 段级弱标签多数票噪声很大：活球长段中确实存在慢节奏组织、伤停、门将持球等低速活球；
  另一方面，弱标签也可能漏掉停表（2/9、6/11、11/14 的缺球后首事件是 `SET PIECE`）。
  两种误差都会把“活球段”拉低。因此段级结果只能做敏感性检查，不能用来证明速度在段级
  无效；需要更多场次或更干净的停顿标签。
- 逐帧阈值不能直接用于段均值；若要做段级判断，应在段级重新选分界值或使用段内持续
  时间/比例，而不是复用 1.39 m/s。
- 开球后球速比球员整体速度更早、更尖锐，适合确认“球已经启动”；球员加速更适合确认
  “比赛已经进入跑动”，不适合定开球时刻。

### 未知

- 本场 142 段长缺球里，真实 D / 活球各多少；没有答案，无法判断低速活球段是真活球
  还是弱标签漏标。
- 本场球全程可见的哨响停表能否被 F1/F3 识别；本实验没有这类标签，不能回答。
- 阈值在更多比赛、不同数据商、不同 fps 和不同速度来源下是否稳定；目前只有 3 场
  Metrica + 1 场 SkillCorner，且只有一次 Game 1/2→Game 3 留出。
- 与 Smart Tagging 结合时，速度确认会不会覆盖真实标签、或把可见停表拖晚；未测。
- 守门员、阵型、比分和比赛阶段对整体速度的影响；本实验没有分层。

## 8. 限制

1. **弱标签不是官方真值**：Metrica 的 D 来自事件顺序规则，SkillCorner 的 D 来自
   phase 补集；两者都不是官方 corrected tracking 的 dead 标记。
2. **段级样本少且标签有噪声**：活球长段每场只有 9–14 段；按多数票分类会丢掉 D/H/A
   混合的段，段均值也会把边界帧混进去。2/9、6/11、11/14 的缺球后首事件是 `SET PIECE`，
   疑似弱标签漏标死球；去掉后 Game 3 只剩 3 段，段级 AUC 没有解释力。
3. **SkillCorner 覆盖偏斜**：D 帧只有 49.9% 有可用球员速度，H/A 99.9%；SkillCorner
   的逐帧 AUC 只代表“有追踪的死球帧”，不代表全部 D。51 个 >5 s 缺球段没有可用特征。
4. **速度来源不同**：外部 `_s` 是位置差分，本场 ATD 是原始速度列；两边都做了 1 s
   后向平均，但短时噪声不能视为等价。
5. **特征定义固定但有选择**：`F2` 的 2 m/s、`MIN_PLAYERS=5`、`F3` 不做二次平滑、
   Q2/Q3 的 0.2/0.5 m/s 和 50% 规则都是事先定的工程定义，不是从本场答案拟合的。
6. **Q2 的事件时间**：Metrica 记录的是犯规/出界发生时刻，不一定是哨响；对照 PASS
   是随机抽样，不代表所有活球事件。
7. **Q3 的 SET PIECE 异质**：包含开球、掷界外球、任意球、角球等；球速和球员加速
   的形态不同，未按子类型分层。
8. **Q4 没有标签**：2-means 是描述性切分，不是显著性检验；1.39 m/s 阈值来自外部
   逐帧数据，直接用于段均值只作诊断。
9. 本场只做无答案的分布观察；代码和本文都没有本场帧号或时刻，也没有修改任何算法、
   模拟器、观测加载器、转换代码或已完成实验。

## 9. 如果要接进 dead_ball_aware（只写建议，不实现）

最可能的用法：

1. **作为长缺球的二次确认，而不是 D 的起点**：球缺球超过若干秒后，如果 F1 在接下来
   1–2 s 持续低于某个分界值（外部数据约 1.4 m/s），才把这段判成 D；如果 F1 仍高，
   保留上一 H/A 或标不确定。这样能减少“活球中途缺球 >5 s 直接判 D”的误判，但 D 起点
   会比现在更晚。
2. **用 F3 的持续负值做减速确认**：F3 最低点约在事件后 1.2–1.7 s，比 F1 的 50% 下降
   更早；可以要求 F3 连续若干帧为负，作为“球队整体在停下来”的证据。风险是活球中的
   正常减速也会触发。
3. **开球确认用球速，球员速度只做辅助**：球速在 SET PIECE 后 0.2–0.5 s 就起来，球员
   整体要 1.4–1.5 s；所以球员加速不适合定开球时刻，适合确认“球已经进入比赛”。
4. **不要复用逐帧阈值做段级判断**：段均值上的 1.39 m/s 会把 42/139 段判成活球，
   远多于 2-means 的 18 段高尾；段级需要单独校准或使用持续时间/比例。

风险：

- 慢节奏活球（组织、伤停、门将持球、角球前站位）会被判成 D；快速死球（球员快速跑位
  准备任意球/角球）会被判成活球。两者在外部数据里都存在。
- 1 s 平滑和 1–2 s 确认会固定增加延迟，不能恢复哨响的精确起点；如果用它替代现有的
  缺球/慢球证据，D 的起点可能更晚。
- 守门员和阵型会污染整体中位数；本实验没有身份，无法剔除。
- 外部阈值只在 3 场 Metrica + 1 场 SkillCorner 上检查，且外部速度是位置差分；本场
  ATD 速度来源不同，直接迁移有风险。
- 本场没有答案，不能证明速度确认会提高官方 spellF1；它只是提供了一个可解释的
  辅助证据，应与出界、缺球、Smart Tagging 等显式证据并列，而不是单独替代。
